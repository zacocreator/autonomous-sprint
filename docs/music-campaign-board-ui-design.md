# Music Campaign Board UI Design Proposal

## Status

Review required before implementation.

このドキュメントは、短期MVP「軽量な Music Campaign Board」の次UI改善に向けたレビュー用デザイン方針です。

実装前にユーザー確認を行うための提案であり、この時点ではコード変更を開始しません。

## Product Position

Music Campaign Boardは、音楽活動向けの軽量カンバンです。

対象は、個人または小規模チームで、コンペ、投稿祭、配信リリース、制作案件などに向けて複数の曲案や制作タスクを管理するユーザーです。

このプロダクトは、汎用タスク管理ツールの完全代替ではありません。音楽活動に必要な最小限の構造を最初から持ち、手動でもすぐ使えることを優先します。

## Corrected Information Model

前回の実装では「行」を曲、MV、告知、投稿準備などのワークストリームとして扱っていました。

これは今回の意図とずれています。

正しい基本構造は以下です。

```text
Project
  例: ボカコレ2026夏 / DTMコンペ / 配信EP制作 / 歌ってみた月間企画

Song Row
  例: 曲案A / 曲案B / メイン曲 / 予備曲 / コラボ曲

Task Card
  例: 構成を固める / 仮ミックス / 歌詞 / イラスト依頼 / 動画 / 投稿文 / 提出確認
```

### Primary Model

- Project: コンペ、投稿祭、リリース、制作案件などの活動単位
- Row: そのProject内の曲単位
- Card: 曲に紐づく作業、素材、依頼、確認事項
- Column: 作業状態

### Secondary Model

曲に直接紐づかない作業は、専用の共通行として扱います。

例:

- 共通準備
- 告知
- 提出 / 配信登録
- ライブ準備

ただし、UIの基本認識は「曲ごとの行」です。

## Target UI Mood

方針は以下です。

- Asanaのように、タスクを消化していく気持ちよさがある
- Linearのように、静かでシンプルで、状態が分かりやすい
- 音楽制作向けだが、過度に装飾しない
- 業務ツールとしての密度を保つ
- 入力負荷を増やさず、手動で続けられる

## Avoid

以下は禁止または避けます。

- 過度な角丸
- AIツールにありがちな太いボーダー強調
- グラデーション背景
- 大きなカードを並べるだけのUI
- カードの中にカードを入れる構造
- カラフルすぎる状態表現
- 汎用タスク管理ツールの完全コピー
- 曲以外の作業カテゴリを行の主役にすること

## Visual Direction

### Shape

- 角丸は4pxから6pxを基本にする
- カード、パネル、ボタンを過度に丸くしない
- ボードセルやカードは罫線に頼りすぎず、面の差と余白で区切る

### Color

- 背景は落ち着いたneutral surface
- Primary colorは主要アクションと選択状態に限定
- 状態色は控えめに使う
- Critical / Warningは小さなラベルまたは左端の細いインジケータで示す
- 画面全体を青系だけで構成しない

### Typography

- Page title: 24px前後
- Section title: 16pxから18px
- Card title: 13pxから14px
- Metadata: 12px
- 文字間隔は0
- Hero風の大見出しは使わない

### Density

- Asana寄りに、カードは軽く読める
- Linear寄りに、行間とメタ情報は整理する
- 1画面で複数曲の進捗を比較できる密度を優先する

## Proposed Layout

```text

│ Sidebar       │ Header                                       │ Detail Panel │
│ Project list  │ Project title / deadline / quick status      │ Selected     │

│               │ Row: 共通準備 | ...                           │              │

```

## Board Structure

### Columns

初期案:

- アイデア
- 次にやる
- 作業中
- 待ち
- 確認中
- 完了

列名は短く保ちます。

### Rows

基本は曲ごとの行です。

例:

- 曲案A
- 曲案B
- メイン曲
- 予備曲
- コラボ曲

共通作業が必要な場合のみ、下部に共通行を追加します。

例:

- 共通準備
- 告知
- 提出

### Cards

カードは作業単位です。

カード上に常時表示する情報:

- タイトル
- 種別
- 期限
- 待ち/依存の有無
- リスク小ラベル

カード上に常時表示しない情報:

- 長い説明
- 素材状態の詳細
- 権利メモ
- 依頼条件
- 長い次アクション

これらは右詳細ペインで扱います。

## Interaction Model

### Primary Actions

- カードをドラッグして状態列を移動する
- カードをクリックして詳細ペインを開く
- 行の「+」からその曲に紐づくカードを追加する
- Project listからプロジェクトを切り替える
- 新規Project作成時にテンプレートを選ぶ

### Secondary Actions

- 詳細ペイン内で状態を変更する
- 詳細ペイン内で曲行を変更する
- 一覧ビューでまとめて編集する

### Mobile

モバイルでは横方向の大型ボード操作を主にしません。

モバイルの優先体験:

- 曲行ごとの折りたたみリスト
- カードタップで詳細編集
- 状態変更は詳細内select

ドラッグはデスクトップの主操作です。

## Readiness Integration

Readinessは独立したチェックリストにしません。

ボード上の状態から自然に出します。

例:

- 締切7日前なのに、曲行に「作業中」以上の音源カードがない
- 曲ごとに動画カードが「待ち」で止まっている
- 複数曲が「アイデア」に残ったまま締切が近い
- 共通提出準備が未着手
- 待ちカードに依存先や期限がない

## Initial UI Improvement Scope

次に実装する場合の推奨スコープは以下です。

### In Scope

- 行の基本単位を曲へ変更
- テンプレートの行構造を曲中心へ修正
- 共通準備行を補助として追加
- ボード上の視覚密度を改善
- 過度なボーダー強調を減らす
- 角丸を控えめにする
- カード表示をよりAsana風に軽くする
- 詳細ペインをよりLinear風に整理する

### Out of Scope

- 本格的なAI診断
- DAW連携
- 外部サービス連携
- チーム権限
- 課金
- 複雑なガントチャート

## Open Review Questions

レビューで確認したい点:

1. Project配下の行を「曲ごと」にする理解で合っているか
2. 共通準備、告知、提出などを「共通行」として下部に置く方針でよいか
3. 投稿祭/コンペ/配信リリースのテンプレート行構成は自然か
4. Asana寄りの軽さとLinear寄りのシンプルさのバランスはこの方向でよいか
5. 過度な角丸、太いボーダー強調を避ける方針で問題ないか
6. 次の実装では、まず曲行モデルとUIトーン修正を優先してよいか
